# POC-B：Android 文游运行时能裁剪到什么程度？

## Question

基于 POC-A 可运行的 Android 基线，移除文游不需要的能力后，最小可用运行时包含哪些依赖，实际下载体积、安装占用和性能如何？

## Work

- 对比完整 DSH 与最小 Profile/运行时的依赖树，逐项说明保留或移除原因。
- 只为第一阶段文游闭环构建裁剪原型，排除 Shell、终端、手机自动化、任意动态插件和开发工具链。
- 在记录清楚型号、系统版本和构建版本的设备上测量 APK 下载大小、安装后占用、首次启动、冷启动和内存。
- 输出实际许可清单，包括被打包的预编译文件、传递依赖和运行时资源；未查明来源的依赖不得纳入候选构建。

## Acceptance

- 提供可复核的裁剪清单、依赖闭包和许可证来源，不仅给出总大小。
- 完成文游闭环所需能力均通过验证，移除项无法从用户输入或插件恢复执行。
- 提供真实构建和实体设备测量值，并给出可供产品决策的体积/性能取舍；不自行虚构“轻量”阈值。
- 如裁剪后仍不满足后续设定的目标，明确建议停止 Android 路线或重新评估运行底座。

## Risks

- WebView/Node/原生模块可能形成不可裁剪的体积下限。
- 上游依赖或二进制运行时可能有单独许可证、更新或应用商店要求。
- 体积与启动体验会随架构、渠道、设备和下载方式而变化。
