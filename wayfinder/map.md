# 本地优先 AI 文游开发地图

## Destination

找到一条经过验证的手机端技术路线，并据此写出可交给实现阶段的 MVP 规格。到达终点前，Android/iOS 运行方式、依赖与许可证边界、轻量目标及核心用户门槛都应有证据支持。

## Notes

- 已敲定的产品阶段和运营边界见[项目方案](../docs/project-plan.md)；本地图只记录尚待验证的路线。
- 优先使用现有成熟能力；保留用户数据在本地、用户自带 API Key、无电脑依赖、最小权限和避免任意代码执行等约束。
- 先完成三个 POC，再决定 MVP 投入。未测得的大小、性能和兼容性不写作既定指标。
- 未完成 POC 和目标用户验证前，不启动 MVP 实现；是否进入游戏引擎阶段另设市场门槛。
- 第三方代码只在逐版本核实许可证及依赖闭包后考虑复用；MIT 项目级许可证不自动覆盖所有依赖和资源。
- 本地 Markdown tracker 的文件关系约定见[Wayfinder 记录方式](README.md)。

## Decisions so far

本地图尚无已关闭票据。已确认的产品方向记录在项目方案中，不冒充本地图已完成的技术决策。

## Not yet specified

- 玩家常用设备与 Android/iOS 占比，以及首发平台顺序。
- 用户能否接受自备 API Key、不同服务商配置体验和直接承担模型费用。
- 在真实设备上的安装/下载体积、首次启动、内存和最低系统版本门槛。
- 两端应用商店政策、API Key 与本地数据保护、内容权利，以及完整产品发行时的第三方许可证审核要求。
- 导入格式优先级、存档兼容范围、用户验证方案，以及 MVP 进入条件。
- 若验证通过，如何把播放器扩展成 Harness；何种市场信号才足以启动游戏引擎阶段。

## Out of scope

- 本轮不做业务后端、用户数据托管、云端模型代理或必须连接电脑的配套客户端。
- 本轮不开发完整游戏机制、创作者市场或大规模生产级应用；这些工作必须等 POC 和用户验证后另行定范围。
- 不直接复制 DSH Go、DSH Mobile 的应用代码，也不引入 AGPL 应用代码；不打包 Ubuntu/PRoot、任意 Shell 或动态代码执行能力。
