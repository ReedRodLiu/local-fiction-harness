# 自然语言单入口、单一 Markdown 设定与无感 Harness 资料分层

> 取代 [ADR 0002](0002-blueprint-extraction-with-full-raw-script-anchoring.md)，并演进 [ADR 0011](0011-three-mode-markdown-harness.md) 的前端心智与资料入口。依据 [V0.2-DECISION-01](https://github.com/ReedRodLiu/local-fiction-harness/issues/82)。

## Decision

- **废除 `StoryBlueprint` 双轨结构**：彻底移除结构化 JSON 蓝图拆解、6 字段蓝图表单与「原始剧本锚定 / 候选剧本」界面概念。故事、作品与角色均回归单一 Markdown 设定文档（按模式展示为「故事设定 / 作品设定 / 角色设定」）；文件或 DeepSeek 存档导入后直接整理为「故事设定」进入主舞台，不再以确认表单前置拦截。
- **欢迎页自然语言单入口**：去掉前置三模式必选开关与模式专属表单。首句由模型轻量语义路由至 `文游`、`写故事` 或 `角色互动`；意图模糊时进入未落盘的中性对话态自然承接，待意图明确后再自动生成对应资产。纠偏采用「对话内自然语言切换 + 顶栏低调模式切换」双通道；导入动作收进单输入框旁的 `+` / 导入菜单。
- **用户视角两层资料 + 折叠分支笔记**：普通用户仅感知「当前设定（故事/作品/角色设定）」与跨场景「我的记忆」两层显性资料；分支级局部文档作为「分支笔记」在后台自动维护并默认折叠。三区上下文预算、Token 估算、文档版本 ID 与节点诊断等 Harness 工程细节统一下沉至「设置 → 高级排障」。

## Considered Options

- **保留 `StoryBlueprint` 只读摘要并与 Markdown 双向同步**：需要维护双份真相与标题匹配修补逻辑，且解析降级仍向普通用户暴露工程概念，违背「Markdown 能解决就用 Markdown」原则。
- **保留欢迎页模式切换或纯关键词静态路由**：前置分类打断自然表达，静态关键词难以处理开放式起手语与跨模式过渡。
- **继续在主界面暴露三层作用域与版本底稿细节**：术语密度高，普通用户难以区分容器/局部/底稿，也易因模态核对弹窗中断沉浸体验。

## Consequences

- 存量含 `StoryBlueprint` 与 `rawScript` 字段的本地故事与旧 `.lfh.json` 备份需在 V0.2 静默迁移中无损并入单一 Markdown「故事设定」。
- 资料持久改动改为对话内非阻塞「提案确认卡片」（人话摘要 + 可展开预览 + 可撤销），具体协议与持久化契约由后续决议锁定。
