# 三种模式共用 Markdown 与确认流程

采用。依据 [通用 Harness 决议](https://github.com/ReedRodLiu/local-fiction-harness/issues/74#issuecomment-7034583672)。

用 Markdown 保存用户可编辑的创作资料，LLM 理解设定、身份、冲突、摘要以及持久改动的意图。客户端保证作用域和版本选择、确认、按路径读取、本地保存与恢复。文游、产粮和人机恋共用节点路径、版本和确认流程，各模式用自己的聊天提示与界面。

- 公共记忆在请求开始时读取最新版。已有路径继承所选节点对应的容器与局部版本。确认编辑后，从所选位置继续时可采用该修订，兄弟路径保留各自版本。每条新回复记录实际读取的版本，回复生成后确认保存的进度另存。
- 流式回复可附一个结构化 Markdown 提议。客户端按请求使用的底稿展示，用户确认后才保存。过期底稿须重新核对。恢复旧版本也生成新版本。普通纠正、临时身份和重访由聊天处理。
- [ADR 0002](0002-blueprint-extraction-with-full-raw-script-anchoring.md) 原先分开的原剧本与已确认蓝图设定合入故事文档。原文保留，明确确认的修改优先生效。可重新生成蓝图预览。DeepSeek 导入候选经过确认后才成为故事资料。
- [ADR 0003](0003-three-zone-context-and-node-summary-snapshots.md) 的节点快照保留为进度覆盖位置。当前进度正文来自路径 Markdown。浏览旧节点和切换路径只恢复位置；续写需压缩时，失败或截断沿用最后一次成功的覆盖。原文放不进预算时提示重试。采用 [ADR 0008](0008-zero-content-diagnostics-and-turn-context-integrity.md) 的路径校验，损坏的引用不得提供上下文。
- 故事 v2 JSON 携带故事有关版本和审计引用。可读 v1 并重建局内资料，历史请求缺少审计时显示未记录。故事备份里的公共记忆只留引用。DeepSeek 导入保留所选会话可读的原附件，附件不作为模型请求的二进制资料发送。Web 使用 IndexedDB，Android 使用应用私有存储。作品正文和所选角色对话可独立导出 UTF-8 Markdown。
- 首版沿用 DeepSeek 官方 BYOK 的文本流。全文进入所选作用域的上下文。有真实预算数据后再决定是否分区加载。
