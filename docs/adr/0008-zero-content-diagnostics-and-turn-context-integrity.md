# 零正文脱敏诊断导出与推演前置上下文完整性保障

## Decision

面向快速迭代与内测排障，客户端默认在本地维护 30 分钟循环诊断缓冲（关键错误同步落盘防白屏丢失），仅在用户主动触发崩溃弹框或设置导出并明文预览确认后，生成严格剔除所有剧本、对话正文、分支命名、原始附件名与 API Key 的**脱敏诊断包（Diagnostic Bundle）**（官方端点保留白名单域名、第三方中转只输出短哈希并剥离路径参数，按勾选附带去正文树骨架），通过既有本地文件分享/复制接口交付，并在 `PlatformRuntime` 预留只写 HTTP 上报扩展缝而暂不自建日志服务器。同步加固核心推演流程：在续写或分支前若父路径未覆盖轮次超出近期预算，由 Harness 先分段滚动补算 `PlotSummarySnapshot` 再发出正文请求，并对已锚定入 `Raw Script` 的**设定提交节点（Setup Node）**在近期窗口与摘要压缩中折叠去重。

## Considered Options

- **接入邮箱 `mailto:` 或静默后台埋点**：普通移动端玩家常无可用系统邮件客户端，且静默上报与未托管服务端承诺及隐私期望冲突。
- **仅在回复完成后事后压缩摘要，且整轮保留导入剧本消息正文**：会导致延后填 Key 开局或中途节点回溯分叉时“先失忆生成一轮再补算”，并让长 `.docx` 剧本在系统区与近期窗口内双倍占满 Token 预算。

## Consequences

- 无业务后端前提下即可通过玩家手传脱敏包精准复现树形拓扑与 DeepSeek 新版字段问题，未来接入极轻 `POST` 接口无需重写采样逻辑。
- 长线导入故事首轮续写及回溯重开可即时具备连贯摘要，代价是极端超长未压缩路径首次续写前会按固定批次先行完成增量摘要压缩。
