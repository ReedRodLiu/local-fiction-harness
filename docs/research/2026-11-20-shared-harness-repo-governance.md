# Agent 仓库的 Markdown 指令与治理有哪些可复用做法

2026 年 11 月 20 日 · Wayfinder 研究票据 #68

## 结论

共用 Harness 提供 Markdown 文档的用途、创建与维护公约，由程序管理文档的读写范围、生效和撤销。每个对话或剧情的具体规则与设定由用户维护。人设、背景故事、用户的角色画像都可以作为文档用途的例子。同一用途可以由不同对话或剧情分别使用。默认按当前范围读取文档和记录，文件名、数量、文档实例是否共享及架构留待独立地图讨论。

## 四个一手来源

1. **AGENTS.md 官方约定。** 仓库根目录提供一个可预期的项目说明入口，使用普通 Markdown，无必填字段。可记录项目范围、验证命令和协作约定。官网也描述了子目录的更具体指引及冲突时的就近优先。列出的测试是 Agent 应尝试执行的检查，是否执行、是否通过需要看运行结果。文件约定本身提供的是行为指引。[AGENTS.md 官网](https://agents.md/#how-to-use-agentsmd)
2. **OpenAI Codex 的实际加载。** 项目指令加载器从项目根沿目录链走到当前工作目录，按顺序收集正文。同一目录优先查找 `AGENTS.override.md`，也可配置候选文件名。根默认用 `.git` 识别，可配置其他标记。加载由程序执行，源码保存来源路径并按字节预算裁剪。启动目录决定自动发现范围，文中链接仍要另行读取。文本进了提示之后，模型需要理解并遵循其含义。[Codex 官方加载器源码，固定版本](https://github.com/openai/codex/blob/49f2fc2c1e4824b0a8eb0a15d3d7daeadc6c1523/codex-rs/core/src/agents_md.rs)
3. **OpenAI Codex 的执行控制。** 官方文档区分沙箱和审批策略。前者限制命令能写到哪里、能否联网，后者决定何时需要先取得批准。限制在执行时由宿主施加。由此推得，检查加载记录可以确认模型看到了什么，尝试越界操作并检查状态可以验证权限是否生效。[Codex 官方沙箱与审批说明](https://learn.chatgpt.com/docs/agent-approvals-security#sandbox-and-approvals)
4. **Matt Pocock 本人的公开做法。** 他在《The Home Repo Pattern》中建议共用材料集中维护，各仓库保留自身约定。启动入口用短指引说明需要时到哪里找，也可提示先读目标仓库说明。他给出的整理流程先盘点、展示迁移计划，获批后才修改。各仓库的改动使用新的本地分支，是否推送由用户决定。他也描述了为并行开发使用 Git worktree 的做法。这里的先读后改是工作约定，分支和 worktree 提供版本与工作目录的隔离，执行权限仍取决于宿主。[Matt Pocock，《The Home Repo Pattern》](https://www.aihero.dev/the-home-repo-pattern)

可复用的仓库类比是先约定各类文档的用途和维护方式。AGENTS.md 给 Agent 工作指引，README 介绍项目，术语表维护定义，票据记录待处理事项。同一套分工可以用在多个分支或目录，各范围维护自己的内容。本项目的候选做法是把这种分工用于共用 Harness。[AGENTS.md 官网](https://agents.md/#how-to-use-agentsmd) · [Pocock 的共享与仓库专用材料说明](https://www.aihero.dev/the-home-repo-pattern)

本仓库已有短入口的例子。根目录 `AGENTS.md` 指向票据操作、标签、领域说明和 UI 设计指南，并列出修改 UI 后要运行的审计命令。资料按任务选读，审计结果由程序产出。仓库文档能指明在何处以及怎样操作票据，GitHub 写入仍取决于账号权限及本轮授权。[仓库 AGENTS.md](../../AGENTS.md) · [票据操作说明](../agents/issue-tracker.md)

## 与现有文游的薄对照

基线为本 worktree 的 `509dd06`。程序组装常规续玩请求时，将已有的原始剧本全文放入固定锚定区，同时带上轻量交互约束及可用的已确认蓝图，再加入目标父节点的剧情摘要快照和沿其祖先路径取得的近期对话。剧情摘要记录这条路径上已发生的事及覆盖位置，程序也可沿目标路径补做摘要。原始剧本承载用户提供的设定，剧情摘要则记录派生进度。可借用的是由程序按范围选取输入的做法。可选补充文档的生效与撤销，需要单独查验实际组装的请求。本票以现有全文锚定和分支摘要为对照，是否调整交由独立地图讨论。[原文锚定 ADR](../adr/0002-blueprint-extraction-with-full-raw-script-anchoring.md) · [三区与摘要 ADR](../adr/0003-three-zone-context-and-node-summary-snapshots.md) · [上下文组装](../../src/harness/context.ts) · [续玩与摘要写入](../../src/harness/harness.ts)

## 三个可检验的迁移例子

以下是本项目的验证例子。文游有现有实现和测试可供对照，产粮和人机恋以本票给定的使用方式提出候选检查。

| 场景 | 用户维护或选择的内容 | 宿主可检查的结果 |
| --- | --- | --- |
| **现有文游** | 玩家提供原始剧本和具体约束，当前分支提供续玩的历史。 | 在分叉后的 A 线分别加入独有的摘要文本和近期对话。切到 B 线续玩，捕获发给模型的内容，确认仍有原始剧本及 B 线有效历史，且没有 A 的两处独有内容。读回故事，确认本轮挂在 B 下，切回 A 仍能恢复其路径和摘要。现有分支测试已有类似断言。[分支回归测试](../../tests/harness/slice5.test.ts) |
| **产粮** | 作者维护背景资料，可在自由讨论中主动选用，也可以请模型生成候选段落。 | 新建一份背景资料，由作者指定其在当前讨论生效，核对请求包含该资料。撤销后，核对后续请求停止直接加载该资料。模型的候选段落可随讨论保存，作者明确采用并保存后，正文才在选定位置发生预期变化。 |
| **人机恋** | 用户分别维护本人聊天的相关设定和扮演对戏的角色设定。 | 为两处分别设置独有资料和经历，再相互切换发言。捕获请求并读回保存结果，检查资料、历史、适用的摘要和写入目标均属于当前范围。切回本人聊天时能接上其先前对话，对戏中的虚构事件没有被写成本人的共同经历。 |

## 候选实践与依赖

- **为文档用途写简短公约。** 讲清每类文档用来记什么、由谁创建和维护、在哪种情况下需要读。具体规则由用户填入对应对话或剧情。应用可以按当前范围和用户的选用动作组装请求。Codex 的目录链和 Pocock 的仓库指引依赖目录约定，跨仓库克隆另需 Git 和相应访问权限。
- **让生效和撤销可核对。** 程序按用户选定的范围和生效动作，将文档纳入对应请求。撤销后，后续请求停止直接加载该文档。验证时捕获生效前、生效后和撤销后的请求。已经保存的历史与摘要可能包含曾经吸收的信息，如何处置它们是单独的操作。
- **在保存时核对写入范围。** 以当前对话、剧情分支和用户动作核对写入目标。正常发送可以保存对应对话及派生摘要，维护用户文档或采用候选正文由相应的用户操作触发。模型对这些内容的改动建议由用户采用后才写入。用允许写入和越界写入两种情况核对实际存储结果。应用控制自身的保存接口即可检查这些行为。Git 分支、worktree、提交和推送用于代码仓库协作，命令沙箱、文件系统权限和远端账号权限用于管控相应通用工具。
