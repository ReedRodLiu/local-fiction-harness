# Cakumi 与本地文游 App 对比

2026 年 11 月 18 日

## 结论

Cakumi 和我们争夺同一个迁移场景：DeepSeek 里的长对话到了上限，玩家想在手机上接着玩。Cakumi 把对话迁到 AI 伙伴名下，延续人设、日常互动和跨聊天记忆。我们的独立 Android App 以故事为单位，目标是一起恢复剧本、当前进度和岔路，让玩家能从原来的位置继续演绎。最值得借鉴的是它如何让迁移结果一眼可核对，以及确认完成后如何直接接回游玩。

我们应先在已定的 DeepSeek 导出 ZIP 路线上做好手机端预览、导入结果和续玩入口，把恢复分支、隔离分支记忆做成可验证的体验。公开分享链接值得另测，它的价值是降低单段迁移的摩擦，能恢复的内容则要由样本验证。陪伴式主动消息和付费积分暂不进入本轮。

## 借鉴顺序

| 优先级 | 建议 | 验收方式 |
| --- | --- | --- |
| P0 · 直接借鉴 | 把「从 DeepSeek 继续」作为醒目的来源入口。选 ZIP 后直接预览标题、末段进度、会话及分支数量、附件恢复范围，再提交导入。完成页给本次新增了什么、哪些跳过、摘要状态和「继续这条故事」。把本地读取与需要调用模型、可能产生费用的步骤说清楚。没有模型配置时，先让玩家看到可恢复内容，明确下一步再配置。 | 让种子玩家在 Android 上独立从导出包找到想续的那一条。分别观察从打开文件到确认、到首条续写成功的时间及卡点，记录 API Key 配置在哪里造成退出。 |
| P0 · 差异化 | 把导入预览和游玩共用的竖向剧情树纳入同一个闭环。默认落在 DeepSeek 原先激活的进度，侧枝展开时显示足以区分路线的本地线索。 | 用带附件、两个以上岔路且有互斥剧情事实的测试档，核对树结构和原激活路径。两次切支后各写一轮，检查角色规则、近端进度和分支事件。重启 App 后再检查保存和恢复。 |
| P1 · 改造借鉴 | 把「记忆可见」做成当前路线的剧情回顾。先复用已有上下文概览展示当前路线摘要及其范围。种子测试出现误记后，再验证玩家是否需要纠正或标记重要剧情，并明确该修正作用在哪条路线及其后续回合。 | 用互斥事件检验玩家能否看出记忆来源和更正范围，切支后无串线。 |
| P1 · 有条件探索 | 分享链接作为单段快捷迁移候选。仅用公开的无隐私样本测试链接稳定性、完整性、手机端直读和现有 Web 环境限制。预览中明示来源是公开分享，以及能带回哪些消息、有无剧本附件及分支。 | 若只能得到分享所选文本，将范围限定为续接该段文本，ZIP 继续承担完整故事迁移。若必须新增业务代理或引导玩家公开私密存档，延后。 |
| P2 · 按需验证 | 借鉴「小手机」用短气泡表现角色对话的节奏。先把它当作个别剧本内的表现方式，同一轮仍按一轮存档，正文继续适合长篇阅读。主动私信、表情包生态、平台积分和社区市场暂缓。 | 核心迁移成功后，对有书信或手机戏份的剧本做小样，确认玩家是否能更清楚地阅读人物对话并回溯该轮。 |

当前证据来自录屏、官方页面和仓库检查。Cakumi 的实际导入成功率、完整迁移能力、长期记忆召回、消息触发及版本差异，仍待同一组无隐私样本真机对照。建议优先级为本次研究判断。
