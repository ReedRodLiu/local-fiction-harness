# 可回取上下文压缩实验

本目录只包含 V0.3 上下文压缩对照实验的离线夹具、计量实现和受控运行入口。它不改写 Folio 的正式上下文策略，也不把模拟结果当成真实省费结论。

## 当前状态

- 已运行：30 轮三组离线短跑（每组 10 个连续、10 个多分支、10 个嵌套分支行动）。
- 未运行：DeepSeek 官方 V4.1 Flash 回放、完整 300 / 500 / 1,000 轮矩阵、真实质量盲评。
- 原因：当前任务没有已授权的官方 DeepSeek 测试凭据。没有读取环境变量、应用密钥、用户密钥或其他凭据存储，也没有改用 Go 或其他实验端点。
- 因此两组省费比较均返回 `unavailable / non-official-provider`，界面不得显示金额结论。
- 本提交没有向生产 Settings 接入占位金额或推测性配置。会话级省费展示的 `unavailable` / `available` 最小设计见下文，正式实现仍等待真实 usage 数据路径和官方证据。

## 复跑离线证据

```sh
node --experimental-strip-types experiments/context-compression/run.mjs \
  --now 2026-11-23T00:00:00+08:00 \
  --output experiments/context-compression/evidence/offline-smoke.json
```

输出（`schemaVersion: 5`）包含：

- 每组匿名逐请求 token 用量、可见正文 UTF-16 字符数、首段正文等待、分支切换首轮等待、完成率、完成回合 ID、出站记录所属逻辑回合序列和请求阶段。
- 生成、剧情摘要、回取、重试的独立记录；每条记录标明 `outbound-http` 或 `local`。只有出站请求把缺失或无效 provider usage 计为未知，本地回取的 `usage` 明确为 `null`，不计作零，也不要求 provider usage。实验边界只接受同时具有非负安全整数缓存命中、缓存未命中和 completion 三个计费桶的 usage；通用 SSE 仍可原样保留部分字段，但映射到实验费用时为 `null`。
- 固定历史连续回放逐轮使用当前行动的前一回复作为父节点；离线证据记录输入历史长度与末尾节点，不重复发送最终历史或行动本身。
- B 组使用生产代码的 `selectNodesToSummarize` 与滚动批次口径；每条上下文记录摘要覆盖到哪个节点、已覆盖/未覆盖节点数以及覆盖是否连续。摘要正文和 30 次摘要请求均由固定算法离线模拟，报告明确标记 `deterministic-offline`，不能当作真实摘要质量。
- 固定历史的分支身份、同名角色在不同路线的互斥状态、共享祖先回取、`A → B → A` 与 `A → B → C` 路线切换。C 组只回取分数大于零且不在当前最近六节点内的路线节点；13 组短线索探针验证本路线事实可见、兄弟路线事实不可见。嵌套夹具通过真实 `FictionHarness.runTurn` 连续续写两轮，重载后仍回到原路线；随后通过真实 `FictionHarness.editAndBranch` 从旧轮建立兄弟分支，再重载和双向切换验证原分支不变、兄弟事实隔离。另一个 branched 夹具通过真实 `FictionHarness.regenerateNode` 重试回复，并验证原回复保留、重试兄弟隔离和重载状态。所有模型回复来自进程内假 transport，`providerCalls` 为 0。
- 90 个生成、30 个滚动摘要和 3 个 retry 出站输入都检查兄弟路线禁止事实；背景摘要与 retry 同样保存输入字符数、消息数、策略名称和内容指纹，不保存请求正文。本地回取不计入这些出站输入。
- 官方 SSE usage 若提供 `completion_tokens_details.reasoning_tokens`，实验契约会作为独立元数据保留。`completion_tokens` 已包含该思考 token，费用与总 completion token 只按 `completion_tokens` 计算一次，不会再次相加。
- 明确标记 `mode: offline-simulated`、`providerRuns: 0` 和 `credentialStatus: not-read`。复跑没有读取任何凭据来源。

离线记录中的 token 数和延迟均为固定算法模拟值，`costUsd` 固定为 `null`，不能用于判断真实缓存命中、延迟或费用。延迟 p50/p95 采用 nearest-rank，只覆盖已完成的逻辑生成；逻辑生成包括成功生成或成功 retry，同一 `logicalTurnId` 以最后成功尝试的首段可见正文等待为一个样本。失败尝试、摘要请求和本地回取不计入该分位数。

## 夹具

| 场景 | 原始规模 | 路线数 | 分支深度 |
| --- | ---: | ---: | ---: |
| `continuous` | 300 轮 | 1 | 1 |
| `branching` | 500 轮 | 20 | 2 |
| `nested` | 1,000 轮 | 50 | 3 |

夹具包含原创中文剧本、共享伏笔 `北星七号`、各路线互斥的银印状态，以及同名角色沈砚在不同路线的衣物、左手伤痕和随身物组合。回取提示只含 `沈砚 衣物`、`沈砚 左手` 等短线索，不含答案；测试同时检查本路线应出现的事实和兄弟路线禁止出现的事实。所有用户行动为 1–15 个汉字。生成器固定随机种子后产生稳定拓扑。

## 受控官方运行边界

正式短跑的硬上限定义在 `OFFICIAL_SHORT_RUN_BUDGET`：

| 项目 | 上限 |
| --- | ---: |
| 出站 HTTP 请求（生成、摘要、重试；不含本地回取） | 128 |
| 单操作重试 | 1 次 |
| 单请求输入 | 256,000 token |
| 单请求输出 | 512 token |
| 总费用 | US$0.25 |
| 并发 | 1 |

预检按每次出站请求的固定输入和最大输出，使用缓存全部未命中的最坏价格计算；任何一项越界都会在传输层发出请求前阻止运行。请求数、retry 数、输入/输出 token 必须是安全非负整数，retry attempt 必须在 `0..maxRetriesPerOperation` 内。同一 `operationId` 的 attempt 必须按 `0`、`1` 等连续且唯一；缺 `0`、跳号或 `0,1,1` 这类重复都会拒绝，retry 计划复用原生成操作的 `operationId`。费用和费率为非负有限数，出站并发必须精确等于 1，`0`、小数或更大并发都拒绝。官方短跑还必须使用 `https://api.deepseek.com`、`deepseek-flash`、主生成思考强度 `high`，并显式选择与账单一致的峰谷费率。当前 `--real` 会直接拒绝，因为尚无已授权的官方测试凭据和实际预检记录。

当前固定夹具的离线预检计划为 90 次生成、30 次模拟摘要和 3 次重试，共 123 次出站 HTTP 请求，另有 30 条本地回取记录。本地回取没有上游 usage，不计入 128 次出站上限或费用。最坏出站费用上限 US$0.17205945 仍在 US$0.25 总上限内。这个数字按字节数上界和全部缓存未命中计算，是中断用的保守上限，不是预计账单。

用户省费结论使用严格比较：两组完成逻辑回合 ID 必须按序完全相同、数量与声明回合数一致，且都非空；任一侧为空、少回合、截断或范围错位时都返回 `unavailable`。所有出站 usage 的 `logicalTurnId` 必须关联到该已完成集合，未完成回合上的失败请求费用也会阻止严格结论。报告另设 `rangeSubsets`，在不放宽上述展示结论的前提下，记录双方各自范围、共同有序前缀及该前缀内费用；它只用于实验证据，臂长不同也不会被当作严格省费结论。成功或失败的生成尝试只要属于同一已完成逻辑回合，其每次请求 usage 仍全部计费，完成回合本身只计一次。

## 会话级省费展示设计

当前只定义结果契约，不修改生产 Settings，也不放金额占位符。

| 状态 | 最小展示 | 必须隐藏或避免 |
| --- | --- | --- |
| `unavailable` | 写明“本会话暂无可比省费”，并显示具体原因，例如非官方数据、usage 不完整、模型或费率不同、回合范围不一致；同时显示比较覆盖的逻辑回合数 | 不显示 `0`、负数、单边金额、估算代替值或“预计省费” |
| `available` | 显示对照策略与本会话策略、逻辑回合数、官方模型、峰谷费率、双方实测费用与节省额；候选更贵时写“费用增加”并显示正数增幅 | 不混入离线模拟、缺失 usage、不同模型或不同费率；不把单次会话结果扩展成全局承诺 |

展示位置限定为用户主动查看的单会话比较结果。正式产品只有在真实官方 usage 已持久化、两组完成回合完全一致且费用来源可追溯后，才接入该状态；在此之前不向实时 Settings 添加无数据来源的占位卡片。

## 上游许可证核对

本次仅参考增量压缩、稳定前缀和按需回取思路，没有复制或打包上游代码。固定版本和文件摘要记录在 `upstream-lock.json`。

- `billion-context` `v0.1.216` 根许可证为 MIT 加“终端用户可见产品必须署名并链接仓库”的附加条款。
- 独立 `acp-kernel` `v0.0.101` 根许可证为 MIT 加同类署名条款。
- `acp-kernel` 声明 Node.js 20+；源码在 tokenizer 与 wire 模块使用 `node:module` / `node:crypto`，不能原样作为 Web/Android 纯客户端包。Billion Context 是 Node.js 代理和 agent 适配层，根包还包含 `mysql2`、`zod` 等运行时依赖。

因此本次候选组采用纯 TypeScript 客户端等效原型。若之后纳入上游代码，必须重新锁定分发包、核对包内 LICENSE 与依赖，并在产品文档或“关于 / 致谢”中列出实际采用的组件和仓库链接。
